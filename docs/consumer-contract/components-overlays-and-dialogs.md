# 오버레이와 dialog 컴포넌트 계약

Tooltip은 짧은 보조 설명 표면만 제공하며 light DOM과 stylesheet가 설치된 open shadow root에서 Escape dismiss와 trigger focus를 유지하고, 긴 도움말, validation message, popover, tour, 권한 판단은 소비 앱이 계속 소유한다. 설명이 접근성 이름을 보강해야 할 때만 Tooltip `id`를 넘기고 trigger에 `aria-describedby`를 연결한다.

Menu와 Popover의 fixed panel을 가두는 transform·paint 부모가 있으면 overflow/containment 경계까지 감지해 방향·위치·가용 크기를 보정한다. 긴 내용은 panel 안에서 스크롤하고 공개 props와 기존 DOM 배치는 유지한다.

Popover와 Menu는 설정, 더보기, 필터, 계정 메뉴처럼 가까운 트리거에서 짧게 펼치는 표면만 제공하며 항목 노출, 권한, 라우팅, 필터 의미, 계정 상태 판단은 소비 앱이 계속 소유한다. Menu trigger/panel/item은 tonal surface로 계층을 구분하고 resting/hover border를 사용하지 않는다. Popover는 `closeOnEscape`와 `closeOnOutside`로 dismissal을 명시적으로 보호할 수 있고, 보호 중에도 non-modal 표면답게 outside target focus를 막지 않는다. ARIA Menu는 키보드 탈출을 보장해야 하므로 Escape/outside dismissal opt-out을 제공하지 않는다. 두 컴포넌트는 light DOM과 open shadow root에서 composed click path를 기준으로 내부·외부 입력을 구분하고, trigger focus 복귀, 실제 click target focus 보존, menu keyboard movement 같은 기본 상호작용을 유지한다. closed shadow root는 내부 active element를 확인할 수 없으므로 이 focus 계약의 지원 범위가 아니다. tour, validation, modal decision 역할로 확장하지 않는다. 모바일 keyboard, 긴 옵션, async option, grouped option, virtualized list, 복잡한 collision 요구는 Popover/Menu/Combobox 안에서 계속 키우지 않고 Sheet flow 또는 headless spike로 보낸다.

Menu는 내부 구현으로 Bits UI `DropdownMenu`(`Root`, `Trigger`, `Content`, `Item`)를 ZDP adapter 뒤에서만 쓴다. `ZdpMenuItem` 타입, Root 공개 props·콜백·type, named `trigger` slot, `.zdp-menu*` class는 그대로 ZDP 계약이고 public API는 바뀌지 않는다. `placement`와 `align`은 선호 배치이며 공간이 부족하면 Bits UI `Content`가 방향과 위치를 보정한다. 긴 메뉴는 가용 공간 안에서 스크롤하며 스크롤·리사이즈에 따라 위치를 갱신한다. 자동 portal 없이 기존 Menu 안에 positioner를 추가하며, 정적 CSS의 기존 배치 클래스는 유지한다. 기존 ZDP custom Escape dismiss 공유 순서는 유지한다. Menu는 바깥 pointerdown에서 닫고, 프로그램이 focus를 바깥으로 옮기면 `onfocusout`에서 `flushSync`로 scope를 정리하며 닫는다. 예전에는 바깥 클릭이 완료될 때까지 열려 있었으므로 닫히는 시점이 pointerdown으로 앞당겨졌다.

Popover도 내부 구현으로 Bits UI `Popover`의 `Root`와 `Content`를 ZDP adapter 뒤에서 쓴다. 기존 소비처 정의 trigger와 default legacy slot을 그대로 유지하므로 Bits `Trigger`는 쓰지 않는다. 공개 props, `trigger` slot, `.zdp-popover*` class, token, `role`(`null`/`group`/`dialog`)은 그대로 ZDP 계약이고 public API는 바뀌지 않는다. Bits 중복 dismissal은 끄고 기존 ZDP shared dismissal stack·Escape 순서와 `closeOnEscape`/`closeOnOutside` opt-out을 유지하며, focus가 밖으로 이동하는 것만으로는 닫지 않고 scroll lock도 걸지 않는다. `placement`와 `align`은 선호 배치이며 화면 경계에서 방향과 위치를 자동 보정한다. 긴 내용은 가용 폭·높이에 맞춰 스크롤하고 간격은 ZDP 토큰을 따른다. 패널은 기존 DOM 안에서 배치하며 자동 portal을 켜지 않는다. 정적 HTML/CSS 표면은 기존 CSS 배치를 유지한다. 바깥 닫힘 시점은 Menu가 pointerdown, Popover는 기존대로 포인터 완료 후 click이라 서로 다르다.

Sheet는 right, left, bottom edge panel로 설정, 필터, 보조 흐름을 여는 modal surface만 제공한다. Escape 닫기, backdrop 닫기, Tab 순환, scroll lock, background `inert`, 이전 focus 복귀, `role="dialog"`, `aria-modal` 구조는 Sheet 표면의 기본 동작으로 유지한다. `closeOnEscape` 또는 `closeOnBackdrop`을 끄면 해당 입력은 modal을 닫지 않는다. 비활성 backdrop은 button이나 Close action으로 노출하지 않고 접근성 트리에서 숨기며, pointer 입력 뒤에도 현재 panel focus를 유지한다. Dialog, Sheet, TermSheet가 겹치면 컴포넌트 종류별 고정 순서가 아니라 열린 순서가 실제 stacking order를 결정하고, 아래 layer가 먼저 닫혀도 위 layer의 focus, background isolation, scroll lock을 유지한다. modal manager는 활성 top layer 바깥 DOM 가지를 임시로 inert 처리하고 final close에서 원래 inert 상태를 복구한다. 소비 앱의 조건부 렌더링이 활성 top component를 정상 close 이전에 제거해도 surviving trigger focus, inert, scroll lock, layer metadata를 복구한다. body-level portal host와 open shadow root 안에 modal component가 배치돼도 같은 isolation과 focus 계약을 유지하지만, design system이 portal target API나 mount orchestration을 제공하는 것은 아니다. closed shadow root는 내부 active element를 외부 component가 확인할 수 없으므로 이 focus 계약의 지원 범위가 아니다. Drawer는 별도 컴포넌트로 복제하지 않고 Sheet placement/use case로 먼저 다룬다. 저장, 권한, 데이터 fetch, 라우팅 판단은 소비 앱이 계속 소유한다.

Dismissible surface는 닫혀 있을 때 component별 document listener를 유지하지 않는다. 활성 Menu, Popover, Combobox, Tooltip, Dialog, Sheet, TermSheet는 owner document의 공용 dismiss stack에 활성 순서로 등록되고, 문서당 공유 capture click/keydown listener가 최상단 layer 하나에만 outside click 또는 Escape를 전달한다. `closeOnEscape=false`나 `closeOnOutside=false`인 최상단 layer는 해당 입력이 아래 layer로 관통하지 않게 막는다. Tooltip은 outside-click 후보에서는 건너뛰지만 Escape top layer로는 참여하므로 focus tooltip → Menu → Sheet → Dialog가 실제 DOM으로 중첩돼도 Escape 한 번에 하나만 닫힌다. light DOM과 open shadow root는 `composedPath()` 기준으로 내부 입력과 outside 입력을 구분한다.

Sheet root는 `data-zdp-sheet-placement`, `data-zdp-sheet-size`, `data-zdp-sheet-surface="sheet"`를 남겨 QA와 소비 앱이 surface identity를 확인할 수 있게 한다.

TermTrigger와 TermSheet는 용어 설명을 클릭으로 여는 trigger, right sheet, bottom sheet 표면만 제공한다. `.zdp-term-trigger`는 본문 안 용어를 button으로 열고, sheet가 열린 동안에만 `aria-controls`를 연결하며, `.zdp-term-sheet`는 선택된 용어의 짧은 설명, 긴 설명, 예시, 관련 용어만 보여준다. TermSheet는 detail page 링크나 라우팅 action을 제공하지 않는다. TermSheet는 `open` 요청과 non-null `term`이 함께 있을 때만 modal lifecycle을 활성화하므로 비동기 term이 나중에 도착하거나 열린 상태에서 사라져도 DOM, scroll lock, background `inert`, focus 복귀가 같은 상태를 유지한다. 기본 dialog/title/description ID는 SSR과 hydration에서 안정적이며, 소비 앱이 명시적인 `id`를 전달하는 계약도 유지한다. `.zdp-term-trigger`는 inline interactive text라서 기본 상태에 밑줄이나 입력 필드처럼 보이는 하단 경계를 두지 않고 옅은 강조 배경과 중간 굵기로 클릭 가능한 용어임을 구분한다. hover에서는 배경 형상을 바꾸거나 글자 굵기로 레이아웃을 흔들지 않고 strong ink 색으로 글자를 또렷하게 하며, 좌우 최소 padding과 focus token을 유지하고, 본문 텍스트 선택을 막지 않는다. Escape 닫기, backdrop 닫기, Tab 순환, scroll lock, 이전 focus 복귀는 sheet 표면의 기본 동작으로 유지한다. glossary manifest, locale fallback, 공개 가능 여부, detail page 라우팅 판단은 소비 앱과 glossary pipeline이 계속 소유한다.
TermSheet root는 stable `term_id`를 `data-term-id`와 `data-zdp-term-id`로 남기고, `data-zdp-term-placement`와 `data-zdp-term-surface="sheet"`로 QA와 linter가 선택된 용어 surface를 확인할 수 있게 한다.
TermSheet에는 광고 slot을 넣지 않는다. TermSheet root는 `data-zdp-ad-exclude="true"`를 유지하고, 광고가 필요한 긴 설명은 소비 앱의 별도 detail page에서 다룬다.

Dialog는 modal layer, backdrop, close, scroll lock, focus trap, aria 구조만 제공하며 저장, 삭제, 인증, 결제, 권한 판단은 소비 앱이 계속 소유한다. Dialog, Sheet, TermSheet의 modal registry는 `root.ownerDocument`별 `WeakMap`에 귀속되므로 같은 JavaScript realm에서 iframe이나 별도 document에 mount해도 layer count, nesting level, inert ownership, body scroll lock을 섞지 않으며 반복되거나 실패한 SSR 렌더 사이에도 상태를 공유하지 않는다. 처음부터 열린 modal을 SSR한 소비처는 hydration 뒤 해당 owner document에서 단일 active layer, body scroll lock, background inert가 활성화되고 close 뒤 모두 복구되는 계약을 유지한다.

상위 개요와 금지 경계는 [docs/CONSUMER_CONTRACT.md](../CONSUMER_CONTRACT.md)를 따른다.
